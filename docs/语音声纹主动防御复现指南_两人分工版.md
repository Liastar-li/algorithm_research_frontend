## 一、三十秒看懂这篇论文

### 1.1 它要解决什么问题

现在 AI 可以"克隆"任何人的声音：给它几秒钟录音，它就能合成出以假乱真的语音，用来冒充身份、诈骗、伪造音频证据。

已有的防御分两类：

- **检测类**：合成完之后再去识别"这是 AI 假造的"。缺点是**拦不住**——假音频已经生成、可能已经传播出去了。
- **保护类（主动防御 / proactive）**：在音频**发布之前**就往里加一点东西，让 AI 克隆出来的声音"不好用"。

本文属于后者。论文标题里的 **Active Defense / 保护（protection）** 正是平台里那个 `category: "主动防御"`。

### 1.2 核心洞见一句话

> **人能听出来的维度 ≠ 机器依赖的维度。**
> 把扰动精确地加在"机器敏感、人耳不敏感"的那部分特征上，就能做到「人听着没区别，但 AI 克隆不出来」。

论文管这叫 **人机感知差异（Human-Machine Perception Discrepancy）**。

### 1.3 两阶段流程（重点，记住这张图）

```text
【Stage 1：解耦-重建训练】（学一个"把声音拆开"的工具）
   输入波形 → mel 频谱 x (T×80)
        │
        ├── 内容编码器 Ec ──→ 内容码 c (T'×32, T'<T)   ← 只保留"说了什么"
        └── GE2E 说话人编码器 E_spk ──→ 说话人嵌入 h (256维) ← 只保留"是谁说的"
                    │
                    ▼
              解码器 D(c, h) ──→ x̂ ──→ PostNet ──→ x̂_psnt ──→ 声码器 ──→ 重建语音
   训练目标：重建得像（不丢信息） + 内容不变 + 说话人信息无法从内容里读出（解耦）

【Stage 2：防御扰动生成】（学一个"加扰动"的工具）—— 冻结 Stage 1
   h ──→ 生成器 G ──→ 扰动 δ (256维)
   h_adv = h + α · δ            ← α = 扰动强度（论文 α=0.10）
   x_adv = D(c, h_adv)          ← 用"被污染的说话人嵌入"重新合成
   x_adv ──→ HiFi-GAN 声码器 ──→ 保护后音频
   训练目标（三件套）：
     L_per  感知质量：Mel 频谱接近 + 心理声学掩蔽阈值以下（人耳听不到）
     L_GAN  真实感：GAN 判别器骗过
     L_de   防御力：模拟攻击者克隆后，克隆音与原说话人不像
```

**关键理解点（小白最容易搞错的地方）：**

> 扰动 **不是直接加在波形上**（那是 Voice Guard 等时域方法），而是加在 **256 维的说话人嵌入向量**上，然后重新合成音频。
> 好处：嵌入空间里"机器敏感、人耳不敏感"的方向是**可以学出来的**，所以扰动能打得准；坏处：必须先有 Stage 1 的解耦网络和声码器，工程量大。
>
> 而且论文强调：**如果没有 Stage 1 的显式解耦**，嵌入空间的扰动会"漏进"内容特征，人耳就会听到杂音（这正是 RoVo 等前作的问题）。

| 变体 | DSR ↑ | MOS ↑ | WER% ↓ | Sim_prot ↑ |
|---|---|---|---|---|
| 去掉 L_de（防御损失） | **12.5**（崩溃） | 4.28 | 5.15 | 0.96 |

## 二、必须先理解的 6 个概念（白话版）

不需要你先会写这些算法，但**必须能用自己的话说清楚**，否则后面 debug 会毫无头绪。

### 概念 1：mel 频谱（mel-spectrogram）

音频是"时间 × 采样点"的波形，人耳不直接看波形。语音处理里普遍先把波形转成 **mel 频谱**：横轴是时间、纵轴是频率（mel 尺度，模仿人耳对频率的非线性感知）、格子里的数值是"这个时间点这个频带有多响"。

本文统一用 **80 个 mel 频带、16 kHz 采样率**，所以输入张量形状是 `x ∈ R^(T×80)`（T 是帧数）。

工具：`librosa`、`torchaudio` 都能算。**先跑一遍 librosa 的示例，确认你知道自己拿到的数组形状。**

### 概念 2：说话人嵌入（speaker embedding）

用一个说话人编码器把一段音频压成一个 **256 维向量**，这个向量代表"这是谁在说话"。同一段话换个人说，向量就变。

本文用 **GE2E**（Generalized End-to-End Loss，ICASSP 2018）实现，代码在 <https://github.com/CorentinJ/Real-Time-Voice-Cloning>（论文脚注 2 直接引用了这个仓库）。

**关键**：几乎所有语音克隆系统（YourTTS、VALL-E、AdaptVC…）内部**都**有一个说话人编码器。所以攻击者一定会用它提取身份信息——这就是"打这个点就能防住"的原因。

### 概念 3：内容码（content code）与"解耦"

**解耦（disentanglement）**：把一段语音拆成"说了什么"（内容）和"谁说的"（说话人）两个互不干扰的部分。

本文用 **AutoVC**（ICML 2019）架构做这件事：

- 内容编码器 `Ec`：3 层卷积 + 双向 LSTM，**瓶颈维度 32**（信息瓶颈，逼它丢掉多余信息，尤其是说话人信息）。
- 解码器 `D`：LSTM + 3 层卷积 + 5 层 PostNet（残差精修）。
- 输出内容码 `c ∈ R^(T'×32)`，说话人嵌入 `h ∈ R^256`。

解耦怎么保证？靠一个**说话人分类器** `Ws`（单层，K×256，K=训练集说话人数）：

```text
L_dis = −H(p_s) = −Σ_k p_s(k|c̃) log p_s(k|c̃)
```

白话：**故意让这个分类器猜不出说话人**。猜得越乱（熵越大），说明内容码里越没有说话人信息。优化内容编码器时 `Ws` 冻结不动。

配套还有两个损失：

- `L_rec = ‖x − x̂‖² + ‖x − x̂_psnt‖²`：重建损失，保证不丢信息。
- `L_cd`：内容一致性损失，保证重建前后内容码不变。
- 总体：`L_S1 = L_rec + λ_cd·L_cd + λ_dis·L_dis`，论文用 `λ_cd=1.0, λ_dis=0.01`。

### 概念 4：对抗扰动（adversarial perturbation）与"防御损失"

**攻击者模型**：拿到你的音频 → 用说话人编码器提取 `h_stolen` → 用它去克隆任意内容 `c_arb` → 得到克隆音 `x_clone`。

**防御损失**（论文最核心的一行）：

```text
L_de = sim( E_spk(V(x_clone)), E_spk(V(x)) )     ← 余弦相似度
```

白话：**我要让"用被污染的嵌入克隆出来的声音"，跟"原始说话人"不像**。于是最小化 `L_de`。

消融表已经证明：**去掉 `L_de`，DSR 从 87.2% 掉到 12.5%**。这是整个方法的发动机。

### 概念 5：心理声学掩蔽（psychoacoustic masking）

人耳在某些频率上"听不见"别人的声音——比如高频嘶嘶声会盖住低音。**掩蔽阈值 θ_x(k)** 描述的就是：在这个频率上，多大的扰动我听不出来。

论文用 **MPEG 心理声学模型**（Painter & Spanias 2000）从原始音频算阈值，然后加惩罚：

```text
L_mask = (1/K) Σ_k max{ P_δ(k) − θ_x(k), 0 }
```

白话：**只要扰动的能量不超出掩蔽阈值，就不惩罚；超出的部分按超出量罚**。这样保证"人耳听不到"。

> 实现提示：MPEG 心理声学模型需要自己实现或找现成实现（这是个独立的小工作量）。退路见第 9 章。

### 概念 6：评测指标（写 README 的"验证"章节必用）

| 指标 | 白话 | 期望 |
|---|---|---|
| **Sim_prot** ↑ | 保护后的音频与原始音频的说话人相似度 | 接近 1（人听着还是同一个人）→ 论文 0.95 |
| **Sim_clone** ↓ | 克隆音与原说话人的相似度 | 越低越好 → 论文 0.13 |
| **DSR** ↑ | 防御成功率：`Sim_clone < τ` 的样本占比，τ∈{0.3,0.4,0.5} | 论文 87.2%(τ=0.5) |
| **MOS** ↑ | 主观听感，5 分制，50 人听 | 论文 4.18 |
| **WER** ↓ | 语音识别错误率（用 Whisper-large 跑） | 论文 5.30% |

> MOS 需要人工听测。课程作业里可以找 10–20 位同学各听 10–20 条做小规模 MOS，**在 README 里如实写明"N 人听测"**，不要写成 50 人。

## 四、复现目标要分档，别一上来就追 SOTA

建议按 **L0 → L4** 逐级推进，每一级都有可展示的产出。**默认目标定在 L3**，L4 视时间与算力决定。

| 档位 | 目标 | 产出物 | 验收标准 | 工作量 | 风险 |
|---|---|---|---|---|---|
| **L0** | 把平台链路打通 | 方法 JSON + 假算法服务（返回一段加噪音频）+ 一组样例 | 能在平台上上传 → 处理 → 预览 → 下载 | 1–2 天 | 极低 |
| **L1** | 推理链路跑通 | 用**公开预训练**的 AutoVC/GE2E/HiFi-GAN 串起"音频 → 嵌入 → 扰动 → 合成 → 波形" | 给一段真实语音输出保护后音频，听感基本正常 | 3–5 天 | 低 |
| **L2** | Stage 1 复现 | 自己训的解耦网络（可缩减迭代数） | 重建音频听感接近原音；`Sim_prot(重建)` > 0.9 | 1–2 周 | 中 |
| **L3** | Stage 2 复现（**核心**） | 训练好的生成器 G + 完整三损失 | **能算出 DSR / Sim_clone / WER**，DSR 显著高于"未防御"基线 | 1–2 周 | 中高 |
| **L4** | 指标对齐 + 黑盒迁移 | 复现论文表格 + 消融 + 黑盒 | DSR 接近论文量级（不必完全一致）；至少 1 个黑盒系统 | 1–2 周 | 高 |

### 分档的降级策略（重要）

- **算力不够** → Stage 1 迭代数从 500k 降到 50k–100k；训练集从 80 人降到 20–30 人；**README 里必须写明实际配置和与论文的差距**，这不扣分，隐瞒才扣分。
- **心理声学模型实现不动** → L_mask 权重设为 0，只用 L_mel 约束听感。消融表显示 **w/o L_mask 的 DSR 仍有 84.3%**（几乎不掉），只是 MOS 从 4.18 降到 3.38。**这是性价比最高的一条退路。**
- **训练一直不收敛** → 保留 L1 成果 + 用"简单嵌入扰动"（在 h 上加高斯噪声 / 随机方向）做演示，明确标注"这是简化版，未训练 G"。诚实标注 > 假装复现。
- **GPU 排不上队** → 用 AutoVC 官方**预训练**权重跑 Stage 2 训练（Stage 2 本身只需一张卡 + 少量迭代）。

### 分档的"对外话术"

在 README 里要写清你们做到哪一档。参考表述：

> 本组完整复现了论文的 Stage 1（解耦-重建）与 Stage 2（防御扰动生成）框架，并实现了 `L_per`、`L_GAN`、`L_de` 三个损失项。由于本地算力限制，Stage 1 训练迭代数由论文的 500k 缩减为 100k（训练说话人 80→40），VCTK 测试集规模为 20 人 × 20 句。指标复现结果与论文的对比见下表，差异原因已逐项分析。

#### 2.3 安装踩坑表

| 坑 | 现象 | 解决 |
|---|---|---|
| **装到 CPU 版 torch** | `2.4.1+cpu`、`torch.version.cuda` 为 `None` | **预期行为，不阻塞开发**。PyPI 的 Windows 轮子就是 CPU-only；训练放云上，或按下方"换 CUDA 版"处理 |

| **`torch.load` 的 `weights_only` 变更** | **必须 ≤ 2.5** | **torch 2.6 起该默认值改为 `True`**。AutoVC / GE2E 的 checkpoint 含 `{'model':…, 'optimizer':…}` 这类非张量对象，加载会直接 `UnpicklingError`，预训练权重全部读不出来。2.4.1 是"有 bugfix 且尚未引入该变更"的折中点 |

| Python | 3.9 | torch 2.4 支持 3.8–3.12 ✅ |

#### 2.4 8 GB 显存的训练配置（务必按此调整）

本项目组实测 GPU 为 **8 GB**，原文档假设的 12-24 GB 不适用。Stage 1/2 训练请按下面配置起步：

| 项目 | 建议值 | 说明 |
|---|---|---|
| `batch_size` | **4 ~ 8** | 显存不足时的第一调整项 |
| 训练片段长度 | **截断到 2 ~ 3 秒** | AutoVC 原始按整句训练，8 GB 上很容易 OOM |
| 梯度累积 | `accum_steps = 2 ~ 4` | 保住有效 batch size |
| 混合精度 | **开 AMP**（`torch.autocast` + `GradScaler`） | 显存与速度双赢 |
| `num_workers` | 2 ~ 4 | Windows 下别设太大（多进程 spawn 开销大） |
| Stage 1 迭代 | 论文 500k，先跑 **5k 验证能收敛**，再按周均算力决定 | 分档见第 4 章 |
| Stage 2 迭代 | 论文 200k，同样先 5k 冒烟 | Stage 1 冻结后显存压力小得多 |

> 若显存确实不够，**先降 batch 和片段长度，不要降 Stage 1 的训练轮数**——轮数不够只是效果差，片段太短会让 Stage 1 学不出内容码的时间结构。

#### 2.5 统一 mel 参数表（比装环境更容易毁项目）

论文明确要求 **16 kHz、80 维 mel**（`x ∈ R^(T×80)`），但三个组件的原生配置互不相同：

| 组件 | 原生采样率 | 原生 mel 维 | 原生 hop | 原生 n_fft | 原生 fmin/fmax |
|---|---|---|---|---|---|
| AutoVC 原版 | 22050 | 80 | 256 | 1024 | 40 / 7600 |
| GE2E (Real-Time-Voice-Cloning) | **16000** | 40 | 160 | 400 | 0 / 8000 |
| HiFi-GAN 原版 | 22050 | 80 | 256 | 1024 | 0 / 8000 |
| **本项目统一采用** | **16000** | **80** | **256** | **1024** | **40 / 7600** |

**四条铁律：**

1. **采样率统一 16000 Hz**——GE2E 权重就是 16 kHz 的，改采样率权重直接失效。
2. **Stage 1 训练、Stage 2 训练、推理、评测四处 mel 参数必须完全一致**。不一致时 `x_adv` 和 `x` 的帧轴对不上，`L_mel` 会是一个恒定的大常数，模型学不到任何东西，且**不报错**——这是最难查的 bug。
3. **GE2E 内部的 40 维 mel 不要动**。它只负责提 `h`；我们外部的 80 维 mel 用于 `L_mel` / `L_cd` / 解码器。两者是不同用途的两套参数。
4. **声码器权重的采样率必须和你的模型输出对得上**：HiFi-GAN 官方主推 **22.05 kHz** 权重；
   要用 16 kHz 就必须换成对应的 16 k 权重，**不能拿 22.05 k 的权重去合成 16 k 的 mel**。
   （所以 L1 阶段用 `autovc22k` 预设跑通是最省事的；最终系统按论文用 `paper16k` 时，
   需要一个 16 k 的声码器，或把模型输出重采样到 22.05 k 再合成。）

**落地方式：** 全部封装到 `algorithms/voiceprint_protection/audio_utils.py`，**任何地方都不许再手写 mel 参数**（见第 8 章的"双人接口契约"第 2 条）。

#### 2.5.1 已落地的 mel 契约（两个预设 + 自动断言）

`config.py` 提供两个预设，**除采样率外完全一致**，方便切换：

| 预设 | 采样率 | 用途 |
|---|---|---|
| `paper16k` | 16000 | **论文配置**。最终系统（自己训 Stage 1、评测、平台演示） |
| `autovc22k` | 22050 | **AutoVC + HiFi-GAN 官方预训练权重的原生配置**。L1 阶段快速跑通推理链 |

`audio_utils.py` 里同时提供 `MelSpec.mel()`（单一实现，训练与推理共用）与 `mel_librosa()`（参照实现，用于对齐 AutoVC 权重），并由 `scripts/test_audio_utils.py` **断言两者数值一致**：

```powershell
python algorithms/voiceprint_protection/scripts/test_audio_utils.py
```

输出"契约锁定成功"即表示 mel 参数已锁死，可以开始写 Stage 1。**这一步不做，后面训练会出现"不报错的静默失败"。**

> **本模块已处理的三个隐藏坑**（写代码前务必知道）：
> 1. **mel 刻度与归一化不一致** —— librosa 默认 Slaney 刻度 + Slaney 归一化，torchaudio 默认 HTK 刻度且不归一化，**数值差很多**。本模块统一用 librosa 约定（因为 AutoVC 官方权重就是这么训的）。
> 2. **STFT 居中补零方式不同** —— librosa 补零，torchaudio 默认反射填充，边缘帧会不同。本模块手动做零填充对齐 librosa。
> 3. **log 底数与截断** —— AutoVC 用 `log10(clip(mel, 1e-10))`，不是常见的 dB 换算。本模块按预设统一处理。

### 第 4 步：跑通"最小可运行"推理链（L1 的核心，2–3 天）

> **本步在任务板上的位置**：W2-D2 ~ W2-D5。

**目标：不训练任何东西，先把论文的推理路径用公开预训练组件走通。**

```text
wav → mel (x) → GE2E 预训练 E_spk → h (256)
                       ↓
                 加一个简单扰动 δ（先随机/高斯，α=0.1）→ h_adv
                       ↓
```

**验收标准：**
- 输入一段真实语音，输出一个 `.wav`，能正常播放，**听感跟原音差别不大**（可能略有失真，因为 AutoVC 预训练权重和你的 mel 配置可能不匹配，迭代调参）。

**产出：** `algorithms/<方法ID>/infer.py`（最小版），`scripts/smoke_test.py`。

**坑：**
- AutoVC 预训练权重的 mel 配置与你用的不一致 → 输出是噪音。**必须先读它的 `hparams` / `config` 并对齐。**
- HiFi-GAN 的 `n_mel` 要等于 80，且采样率要匹配（16 kHz 对应的 HiFi-GAN 权重，不是 22.05k）。

### 第 5 步：Stage 1 复现（L2，1–2 周）

**目标：** 训练自己的解耦-重建网络。

顺序建议（**先跑通最小版，再加损失**）：

| 小步 | 内容 | 验收 |
|---|---|---|
| 5.1 | 只用 `L_rec` 训练 Ec + D + PostNet（`h_trg = h`） | 重建音频听感接近原音；`L_rec` 下降 |
| 5.2 | 加 `L_cd`（λ_cd=1.0） | 内容一致性提升 |
| 5.3 | 加 `L_dis`（λ_dis=0.01），`Ws` 冻结 | 说话人分类器在内容码上的准确率趋于随机 |
| 5.4 | 补齐 `E_spk` 的端到端微调（论文说 GE2E 预训练 + 微调） | `Sim_prot(重建)` > 0.9 |

**技巧：**
- 强烈建议**先在小数据上跑通**（5 个说话人、500 句、5k 迭代），确认 loss 曲线合理，再放大。
- `L_dis` 容易训崩：熵最大化不稳定时，先把 `λ_dis` 设 0.001 逐步加。
- 用 TensorBoard 记录 `L_rec / L_cd / L_dis` 三条曲线。
- 保留 checkpoint 的逻辑：每 N 步存一次，`latest.pt` + `best.pt`（按 `L_rec`）。

**产出：** `algorithms/<方法ID>/stage1/`（`model.py`、`dataset.py`、`train.py`、`losses.py`）、训练日志、checkpoint。

### 第 6 步：Stage 2 复现（L3，1–2 周，**论文核心**）

**目标：** 冻结 Stage 1，训练生成器 `G` 与判别器 `D_adv`。

```text
冻结：Ec、D、PostNet、E_spk、V(HiFi-GAN)
可训：G（生成器）、D_adv（判别器）
```

**训练主循环（伪代码，照着这个写）：**

```python
for step in range(total_steps):
    # --- 1. 取一批真实语音 ---
    x, h = load_batch()                       # mel 频谱、GE2E 说话人嵌入
    with torch.no_grad():
        c = Ec(x, h)                           # 内容码（冻结）
        h_adv = h + alpha * G(h)               # 扰动
        x_adv = D(c, h_adv)                    # 保护后 mel
        wav_adv = V(x_adv); wav = V(x)         # 波形（用于掩蔽阈值与 PSD）
        # 模拟攻击：攻击者用 E_spk 从保护后语音提取嵌入
        h_stolen = E_spk(wav_adv)
        x_clone = D(Ec(x_clone_content, ...), h_stolen)   # 克隆音
        wav_clone = V(x_clone)

    # --- 2. 计算损失 ---
    L_mel  = ||x - x_adv||^2
    L_mask = mean_k( max(PSD(wav_adv - wav, k) - threshold(wav, k), 0) )
    L_per  = L_mel + lambda_mask * L_mask
    L_de   = cos_sim(E_spk(wav_clone), E_spk(wav))       # 越小越好
    L_GAN  = (D_adv(x_adv) - 1)^2                        # G 想骗过 D_adv
    L_D    = (D_adv(x)-1)^2 + D_adv(x_adv)^2             # D_adv 想分辨真假

    # --- 3. 更新 ---
    L_G = L_GAN + lambda_de * L_de + lambda_per * L_per
    update(G, L_G); update(D_adv, L_D)   # 注意：D_adv 的目标要 stop_gradient
```

**超参（论文值）：** `α=0.10, λ_per=15.0, λ_de=5.0, λ_mask=0.1`；GAN 用 **LSGAN**（最小二乘 GAN）。

**验收：**
- DSR 显著高于"加高斯噪声"的朴素基线。
- `L_de` 在下降。
- 保护后音频"听着正常"（先自己听，再请同学听）。

**坑：**
- **`L_de` 是让 `h_stolen` 与原始 `h` 不像**——注意是"最小化相似度"。如果实现反了（变成最大化），训练会直接把音频毁掉。**写完先跑 100 步听一下输出。**
- `E_spk` 在 Stage 2 里是**冻结**的（图 1 蓝色雪花=Frozen），但攻击者用的 `E_spk` 与保护者用的 `E_spk` 是**同一个模型**（白盒设定）。
- `x_clone` 的内容 `c_arb` 用**同一批的另一条语音**或**打乱配对**都可以，论文说"arbitrary content"。**建议用同一 batch 内随机打乱配对**，实现最简单且论文就是这么个意思。
- GAN 训练不稳 → 先关掉 `L_GAN`（`λ_GAN` 设 0 或先只训 G 的其他损失），等 DSR 有了再打开。

**产出：** `algorithms/<方法ID>/stage2/`（`generator.py`、`discriminator.py`、`train.py`、`psychoacoustics.py`）、checkpoint。

| `report` | boolean | true | 是否同时返回评测报告 JSON |

> - `protected.wav` 保护后音频
> - `clone_no_defense.wav` 未防御时攻击者克隆出的声音（听起来很像）
> - `clone_with_defense.wav` 防御后攻击者克隆出的声音（听起来完全不像）
> - `report.json`（Sim_prot / Sim_clone / DSR / WER）
>
> **这比单纯"给音频加了点东西"有说服力得多**，而且它直接对应论文的核心论点。

### 7.3 接口协议速查

| 方向 | 内容 |
|---|---|
| 请求 | `POST <endpoint>`，`multipart/form-data` |
| 请求字段 | 各素材文件（字段名 = `inputs[].name`）、`method_id`（字符串）、`parameters`（JSON 字符串） |
| 成功响应 | HTTP 200 + `{"message": "...", "artifacts": [{kind,label,filename,url}, ...]}` |
| `kind` 可选 | `image` / `audio` / `video` / `json` / `text`（1–20 个） |
| 失败响应 | 非 2xx + `{"error": "用户可理解的说明"}`（前端会原样显示，超过 500 字截断） |

> 前端**同步等待**结果（不支持"返回任务 ID 再轮询"），所以接口必须在合理时间内返回（建议 < 60 s）。**训练绝不能放在接口里**——接口只做推理。

## 八、两人分工：都接触算法

### 8.1 分工原则（三条，先说清楚再谈具体活）

1. **不按"算法 / 非算法"切分。** 常见的错法是"一人写模型、一人写文档和前端"。这样写文档的人**无法判断算法结果对不对**，最后只能盲写；而且一旦算法那块卡住，整组交不出来。
2. **按"模块主责 + 影子负责"切分。** 每人有一个主责模块，但对方是那个模块的**影子负责人**：能读懂、能改、能救火、能答辩。
3. **按时间轮换主责。** 第一个里程碑后**交换主责模块**，保证两人都完整经历过两个阶段。

### 8.2 模块级分工

```text
                    ┌──────────────── 共同区（两人 100% 都做）────────────────┐
                    │  config.py / audio_utils.py / 接口契约 / 环境 / 数据准备 │
                    │  infer.py / evaluate.py / service.py / 平台接入 / README │
                    └───────────────────────────────────────────────────────────┘
                              │                              │
        ┌─────────────────────┴──────┐        ┌──────────────┴─────────────────┐
        │ 成员 A（第一轮主责）          │        │ 成员 B（第一轮主责）            │
        │ Stage 1：解耦-重建            │        │ Stage 2：防御扰动生成          │
        │  · Ec / D / PostNet           │        │  · 生成器 G、判别器 D_adv      │
        │  · L_rec / L_cd / L_dis       │        │  · L_per / L_GAN / L_de        │
        │  · Ws 说话人分类器             │        │  · 心理声学掩蔽阈值 θ_x        │
        │  · Stage1 训练循环             │        │  · Stage2 训练循环             │
        │ 影子负责：评测脚本 evaluate.py  │        │ 影子负责：数据管道 prepare_data │
        └───────────────────────────────┘        └────────────────────────────────┘
                              │                              │
                     第一里程碑后交换主责（2 周一次）
```

**为什么这么分：**

- Stage 1 和 Stage 2 是**论文的两个半篇**，各自独立成篇，各自有独立的知识点（解耦/熵最大化 vs GAN/心理声学），适合一人主责一块。
- **评测脚本和数据管道交叉**，保证 B 不会"完全不懂 Stage 1 输出的东西长什么样"，A 也不会"完全没碰过数据"。
- **共同区是刻意设计的**：配置、音频工具、推理、评测、服务、平台接入，两人一起做、一起 review，不允许一人独占。这些恰好是"两个人都得会"的技能。

### 8.3 能力底线：两人都必须做到这 6 件事

写在 README 的分工表里，也当作验收清单：

| # | 能力 | 验收方式 |
|---|---|---|
| 1 | 能画出两阶段数据流，说出每个张量的形状 | 口头互相讲一遍（不能看代码） |
| 2 | 能独立跑通完整推理脚本 | 换一台机器/换个人，只给命令不给解释，能跑出结果 |
| 3 | 能读懂**对方主责模块**的代码并讲解其逻辑 | 每周"主讲日"对方提问 |
| 4 | 能改一个超参并跑出可观察的差异 | 例如把 `λ_de` 从 5 改成 0，看 DSR 崩掉 |
| 5 | 能独立启动服务并在平台上完成一次上传→处理→下载 | 录屏 |
| 6 | 能独立修改方法 JSON 与 README 的对应章节 | 交换改对方的章节，对方 review |

> 第 4 条特别重要：**两人必须都亲手把 `L_de` 去掉跑一次**，亲眼看到 DSR 从 87% 掉到 12%。这是"都接触算法"最硬的证据。

### 8.4 协作节奏（写进日历，别靠自觉）

| 频率 | 活动 | 时长 | 产出 |
|---|---|---|---|
| 每天 | 站会 15 分钟：**昨天 / 今天 / 卡点** | 15 min | 共享待办 |
| 每周 1 次 | **主讲日**：轮流主讲自己主责模块 20 分钟，另一人提问并**复述一遍** | 40 min | `docs/notes/主讲记录.md` |
| 每周 1 次 | **串行跑通日**：两人一起，从头到尾跑一遍完整流程（不许一方代跑） | 2 h | 卡点清单 |
| 每 2 周 | **主责模块交换** | — | 交接文档（`docs/notes/handoff_<阶段>.md`） |
| 每个里程碑 | 交叉 code review：每人 review 对方的 PR | 1 h | review 记录 |
| 随时 | 接口契约变更**必须两人签字** | — | `docs/interface-contract.md` 记录变更 |

### 8.5 双人接口契约（防止"各写各的"的关键）

在 `docs/interface-contract.md` 里写下所有跨模块的数据约定，**任何改动都要双方同意并更新这个文件**：

```text
1. 采样率 16000 Hz，单声道，16-bit PCM
2. mel（唯一真源在 algorithms/voiceprint_protection/audio_utils.py）:
   n_fft=1024, hop=256, win=1024, n_mels=80, fmin=40, fmax=7600
   （GE2E 内部自己的 40 维 mel 不动，它只用来提 h）
3. x      : float32 (T, 80)        T = 帧数
4. c      : float32 (T', 32)       T' = T // 2
5. h      : float32 (256,)         L2 归一化
6. h_adv  = h + alpha * G(h)       alpha 由平台参数传入，默认 0.10
7. x_adv  = D(c, h_adv)            (T, 80)
8. wav_adv= V(x_adv)               16000 Hz（HiFi-GAN 必须用 16k 配置）
9. E_spk  : Stage 2 中冻结
10. 所有随机过程必须用显式 seed（config.py 里的 SEED）
```

**这个文件是两人协作里性价比最高的一件事。** 没有它，Stage 2 拿到 Stage 1 的输出时形状/归一化对不上，会浪费一整天。

### 8.6 常见协作坑与对策

| 坑 | 表现 | 对策 |
|---|---|---|
| 各写各的 mel 参数 | Stage 2 接入 Stage 1 输出全是噪音 | 契约文件 + `audio_utils.py` 唯一真源 |
| 只有一个人能跑通 | 另一个人一换环境就挂 | 每周"串行跑通日"强制执行 |
| 训练在各自机器上 | 无法复现 | 固定 seed、固定 `config.py`、写 `docs/experiments.md` 记录 commit |
| 接口改了没通知 | 联调时才发现不匹配 | 契约变更双方签字 |
| 文档到最后一个人赶 | README 里全是想象 | **实验记录与代码同 commit 提交** |
| 一个人被卡住另一人闲着 | 进度停滞 | 卡住 > 1 天 → 启动"影子负责人"接管 |
| 过度分工导致只会一半 | 答辩时被问到另一半答不出 | 8.3 的 6 条底线 + 主讲日 |

### 8.7 答辩视角的分工（很多组栽在这里）

- 两人**都要能完整讲一遍**全流程（各 10 分钟）。
- 约定：**每人主讲自己主责模块，但对方负责回答对方模块的问题**。
- 提前准备 3 个"刁钻问题"的答案（预算从哪来？DSR 提升是不是因为音频坏了？α 敏感吗？）。
  - 第三个尤其要准备：**"你的 DSR 提升，会不会只是因为输出音频变成了噪声/静音，克隆当然失败？"** —— 正确答案要用 `Sim_prot = 0.95`、`MOS = 4.18`、`WER = 5.30%` 三个数一起说：**音频对人仍然清晰可辨、识别率几乎不变**，所以不是"坏掉"。这是论文最容易被质疑的点，也是最需要你们自己算一遍证明的点。

| **声纹 / voiceprint** | 由一个人的声音携带的、可用于识别身份的生物特征 |
| **零样本语音克隆** | 不需要该说话人的训练数据，只给几秒参考音频就能合成其声音 |
| **主动防御 / proactive defense** | 素材发布**前**就加入防护，使后续 AI 滥用失效 |
| **说话人嵌入** | 一段音频 → 256 维向量，表示"谁说的" |
| **说话人编码器** | 产生说话人嵌入的模型（本文用 GE2E） |
| **mel 频谱** | 音频的时频表示，模拟人耳感知，本文 80 维 |
| **声码器 vocoder** | mel 频谱 → 波形（本文用 HiFi-GAN） |
| **信息瓶颈** | 用低维（32 维）瓶颈迫使网络只保留关键信息 |
| **解耦 disentanglement** | 把语音拆成"内容"与"说话人"且互不干扰 |
| **熵最大化** | 让说话人分类器的预测趋于均匀 → 内容里读不出说话人 |
| **对抗扰动** | 专门用来让模型出错、但人感觉不到的微小扰动 |
| **心理声学掩蔽** | 人耳在某些频带听不到别的声音 → 掩蔽阈值 θ |
| **LSGAN** | 最小二乘损失的 GAN，比原始 GAN 稳定 |
| **白盒** | 攻击者/评测用的模型与训练时相同 |
| **黑盒** | 评测用模型训练时没见过（本文：YourTTS / VALL-E / AdaptVC） |
| **DSR** | 防御成功率，Sim_clone < τ 的样本比例 |
| **MOS** | 主观平均听感分（1–5） |
| **WER** | 语音识别错误率 |
| **t-SNE** | 把高维向量降到 2 维画出来看聚类（论文 Figure 3） |
